# Sprint 1 testing and evidence

## Run locally

Install the dependencies from `requirements-dev.txt`, configure the MySQL database as described in the README, and run:

```sh
python scripts/run_checks.py
```

The student suite covers authorized registration, duplicate IDs, updates that preserve the Student ID, search by ID, partial name and hostel, retained deactivation, allocation restrictions, role access, and a response-time check with 5,000 synthetic records. The hostel suite covers admin-only writes, hostel and room validation, automatic bed creation and capacity changes, and available-bed filtering by hostel, floor and room type while excluding occupied and maintenance beds.

## Saved CI evidence

The current `Django Tests` workflow runs `python scripts/run_checks.py` on Python
3.11 and 3.14 with MySQL 8.4. Open the workflow run associated with the pull
request commit and download `hms-test-evidence-py<version>-<commit>` for the
logs, JUnit XML, coverage and run metadata. Artifacts are retained for 30 days
and uploaded even when verification fails. The runner includes the accepted
Sprint 1 suite; [SPRINT2.md](SPRINT2.md) explains the combined checks.

The evidence is generated by GitHub Actions for each commit; no result is asserted here without a corresponding run.

Historical Sprint 1 workflow runs used `python manage.py test` and artifacts
named `sprint1-test-evidence-<commit>`. Those names describe earlier runs, not
the current workflow.
